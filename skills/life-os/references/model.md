# Life OS 数据模型

对象、字段、取值、关系与时间语义，不依赖存储后端。由谁维护见 [SKILL.md](../SKILL.md)，修改边界见 dazi。

## 通用规则

- 每个对象都有标题和正文；说明、成果标准、范围、来源与决策写在正文。
- 字段名和取值使用下文的标识符，后端默认原样存储。
- 所有字段可选。缺失的字段取默认值；无默认值的字段缺失表示未知。只保存已知的非默认值，有意义的零值照常保存。
- 关系由引用方单向保存，可以暂缺；不保存反向关系、间接关系或派生数据。
- 状态回到默认值时删除该字段。各对象状态独立：Action 完成不等于其 Project 或 Routine 完成。
- 只有 Action 有日期字段；Routine 的 `cadence` 是节奏，不是具体日期。

字段类型：枚举（`a | b`）、文本、数字、日期、布尔（只存 `true`）、关系（`→ 目标对象`，括号内为数量）。

共享字段：

- `parent` → 上级对象。上级链路为 Pillar → Life Aspiration → Goal → Project 或 Routine → Action，可接的类型和数量见各对象；上级的类型由被引用的对象本身决定
- `topic` → Topic（一个或多个）
- `people` → Person（一个或多个）
- `notable`：布尔，值得记住

## 对象

### Pillar

核心价值、意义与希望践行的原则。

### Life Aspiration

长期、宽广且有情感意义的愿景。正文写明希望的状态和边界。

- `status`: `inactive`；缺失 = 有效
- `parent` → Pillar（一个）

### Goal

希望达到或保持的结果，正文写明判断标准。只划定一段时间、没有判断标准的（如"Q3 要做的事"）不建成 Goal。人类还没说清的判断标准，按最合理的理解写下并标为推测，不必等确认；人类看到不对再改。

- `status`: `on_hold | completed | cancelled`；缺失 = 活跃。`on_hold` 是暂时搁置，`cancelled` 是明确不再推进，原因写正文，两者都不算完成。完成或取消时，在正文写下复盘：哪些做法管用、哪些没用。
- `parent` → Life Aspiration（一个或多个）
- `topic`、`notable`

### Project

为 Goal 交付的一批具体工作，有明确完成点，以交付标准判定完成。说不清完成点或看不到尽头的是 Goal；更大的事拆成阶段，只建当前阶段。

Project 记的是人生视角下的这件事：为什么做、到了哪里、卡在哪里、下一步。项目内部怎么做留在它自己的载体里（如代码仓库、项目文档），正文只链接过去。

- `status`：同 Goal
- `parent` → Goal（一个）
- `topic`、`notable`

### Routine

持续重复的推进或维护机制，没有完成点。固定要做的事都建成 Routine，是否到了时候按 `cadence` 和最近一次执行判断。

- `status`：同 Goal
- `cadence`: `daily | weekly | monthly | quarterly | per_release | as_needed`
- `parent` → Goal（一个）
- `topic`、`notable`

### Action

可直接执行的具体事项，包括会议安排。

- `status`: `waiting | done`；缺失 = 待办
- `priority`：数字，越大越重要；缺失 = 0。只表示重要程度，时间约束用日期表达
- `do_date`：日期，计划执行或跟进的日期
- `due_date`：日期，真实的最晚完成约束
- `completed_on`：日期，实际完成日；标记 `done` 时一并记录
- `human_required`：布尔，必须本人完成，包括只有人类能拍板的决定、只有人类能给的信息
- `parent` → Project 或 Routine（一个）
- `topic`、`people`、`notable`

三个日期彼此独立；`do_date`、`due_date` 与 `status` 无关。完成日确实未知时才省略 `completed_on`，未知日期不能用其他日期代替。

### Topic

主题索引，关联知识与工作，不代替项目。

### Neurobit

文章、视频、书籍、文档、会议记录、思考或笔记。值得保存的会议内容是 Neurobit。

- `status`: `queue`（待处理）；缺失 = 不在待处理队列
- `category`: `media | notes | documents`
- `source`：文本
- `goal` → Goal、`project` → Project、`routine` → Routine（各一个或多个，可同时关联）
- `topic`、`notable`

### Person

需要保留关系背景与互动上下文的人物或机构。

- `status`: `inactive`；缺失 = 有效
- `self`：布尔，这段人生的主人，全局只有一个

人类自己也是一个 Person，是 Agent 最重要的一段关系：这个人是谁、怎么与他相处。正文按需分节，例如：

- **关于人类**：处境、经历、偏好、状态
- **平时关注**：要留意什么、怎么判断、到什么程度该提出来。需要按天积累的数值记在 Daily 的字段里
- **约定**：双方说好的做法和边界，包括在 harness 里的安排

每条注明日期，人类说的与 Agent 推测的分开标明；过时的改写或删去。只和某件事有关的知识写进那件事的对象，这里只放关于这个人和这段关系的。

### Daily

每天一篇，人类与 Agent 共写。其他对象按"是什么"组织，只存当前状态；Daily 按"什么时候"组织，是这段人生唯一的时间轴：变化发生在哪一天，以及这一天本身过得怎样。

- 日期标识这一篇，不作为字段保存
- 指标：按需记录，字段名自定
- `notable`

不与其他对象建立字段关系，正文可以链接任何对象。正文记三类内容：

- **变化**：决定、对象的状态变化、转向，都链接到对象
- **这一天本身**：人类的状态和劲头、值得记住的经历和观察
- **Agent 留下的痕迹**：推测，以及它后来被证实或纠正；人类的纠正；对外或不可撤回的动作；不该重复的事，例如提醒过什么、看过哪些来源

一条记录满足任一条件才写：人类日后回看会想知道；Agent 下次醒来没读到会做错或重复做。只写结论，不写过程；理由和细节留在相关对象里，Daily 只链接过去，不复述。反复出现的规律写进人类的 Person，Daily 只记当天的情况。默认不标作者；人类做出或同意的决定标为决定，Agent 的推断标为推测。
